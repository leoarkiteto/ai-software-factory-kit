# Visual design comes from a read-only design-worker, and workers never call Figma

UI requests often come with a visual reference: a Figma frame, or a screenshot. Before this change the kit only carried the request's text. An image pasted into `/factory:start` reached the orchestrator but not the workers or reviewers (subagents receive only their brief), and it was gone on `/factory:resume`. Workers could not call a Figma MCP server either: their `tools` list has no MCP tools, and plugin agents ignore `mcpServers`.

The kit adds a design reference step, modelled on external research (ADR-0013). A read-only `design-worker` reads the cited frames or images once, maps them onto the repository's theme and components, and returns a design note. The orchestrator saves it to `.factory/workflows/<id>/design/D<n>.md`, records it as the list artifact `design`, and passes it to workers through task scope and constraints, and to reviewers through the review brief.

## Decisions

- **A separate role, not Figma tools on every worker.** One extraction serves every task, so parallel workers build from the same version of the design and the Figma rate limits (200 calls a day on Professional) are spent once. The design is frozen for the workflow: later edits in Figma do not change what was approved. Layer names and texts in a design file can carry injected instructions, so Figma content stays in an agent that cannot write files or run commands.
- **Kind `researcher`, reused.** The design-worker changes no files and never takes DAG tasks, which is exactly what the kind already enforces (`validatePlan` rejects non-worker roles in the DAG). A separate `designer` kind would change the schema and checks without changing any behaviour.
- **Model tier `efficient` (Sonnet), not `light`.** Unlike research, the work is not retrieval. The agent reads images, maps Figma variables onto existing theme tokens, and must notice what the design leaves out. A wrong mapping becomes a task constraint that the worker follows and the reviewer checks against the same note, and a missed gap means nobody is asked. The agent runs once per workflow, so the cost of the stronger tier is small. Repositories can move the role in config.
- **Tools `Read, Grep, Glob` and four Figma MCP wildcards, no web, no Write, no Bash.** `mcp__figma__*` (remote server added by hand), `mcp__plugin_figma_figma__*` (Figma's Claude Code plugin), `mcp__claude_ai_Figma__*` (claude.ai connector) and `mcp__figma-desktop__*` (desktop server). Wildcards that resolve to nothing are dropped, as with Context7. The remote server, directly or through the plugin, is the supported path. The desktop server is best effort: its `get_design_context` reads the app's current selection, which an unattended agent cannot rely on.
- **Triggered only by an explicit citation.** The step runs when the request cites a Figma link or an image path in the repository. The orchestrator does not go looking for designs: an old mockup found in `docs/design/` must not drive a change nobody asked it to. An image pasted into the conversation, not saved in the repository, makes the orchestrator pause and ask for it to be saved under a repository path.
- **What the design shows is a requirement; how to map it is advice.** Layout, states, texts and hierarchy come from the user's own citation, so workers and reviewers treat them as requirements. Token and component mappings are the agent's proposal and the plan may change them. When the design and the request's text disagree, the orchestrator asks.
- **Gaps stop or surface, never get guessed.** A missing state or screen changes behaviour: the orchestrator asks. A value with no theme token is never written as a literal: the plan maps it to the nearest token or adds a task for a new one, and records the choice under Risks. A missing asset makes the orchestrator ask for the file, or for permission to use a marked placeholder.
- **Figma's generated code is a source of specification only.** `get_design_context` returns React and Tailwind by default, which does not fit React Native and rarely fits a repository's components. The note gives specifications, never code to paste.
- **A call budget per brief**, about 10 Figma calls by default, like research's page budget.
- **Images through `factory-state fetch-design-image`, not `curl`.** The design-worker sees screenshots but cannot save them, and the remote server's URLs expire. The orchestrator downloads them at once with a zero-dependency subcommand (ADR-0002): HTTPS on Figma hosts only (or the desktop server's loopback origin), every redirect hop re-checked, PNG or JPEG by magic bytes (SVG refused: it is text and can carry script), at most 10 MB, written atomically to `design/D<n>-<node>.<ext>` and recorded as a `design` artifact. It runs under the existing `Bash(factory-state *)` permission, and signed query strings are never echoed. When the download fails, the orchestrator asks the user for exported PNGs instead.
- **Figma unavailable means asking, not skipping.** If the request cites Figma but no Figma tools resolve, or the role is disabled, the agent reports `blocked` and the orchestrator asks for PNG exports of the frames. Going on without a design the user cited would ignore the request.
- **No visual verification.** No agent runs the app and compares it with the design; in React Native/Expo that needs a simulator and has no reliable automation. The final report lists a manual item: compare the running app with the design note, state by state.

## Consequences

- The kit does not install or bundle a Figma MCP server. It needs a Figma account with a Dev or Full seat on a paid plan. With a View or Collab seat (20 calls a month) the PNG path is the practical one.
- The allowed download hosts and the tool-name prefixes are inferred from Figma's documentation and from how Claude Code names other servers. Both are to be confirmed by a real-session probe and recorded in `docs/research/phase-12-figma-design.md`; until then the host list in `lib/design.mjs` is provisional.
- The behavioural evals cover the repository-image path only: the eval sandbox has no Figma. `fetch-design-image` is covered by `node:test` against a local HTTP server.
- Figma content is data. The agent prompt and the procedure tell it and the orchestrator to ignore instructions found in layer names, texts or descriptions; this is a prompt-level rule, not an enforced one.
